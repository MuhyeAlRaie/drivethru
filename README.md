# 🚗 درايف ثرو — تطبيق طلبات درايف ثرو (عميل + كاشير + مطبخ)

تطبيق ويب خفيف جداً (HTML + CSS + JavaScript فقط — بدون أي إطار عمل) مخصص للمطاعم التي تعمل بنظام درايف ثرو، بثلاث شاشات:

| الشاشة | الملف | الوصف |
|---|---|---|
| واجهة العميل | `index.html` | تتحقق من موقع العميل (GPS) وتفتح المنيو فقط لمن هو داخل نطاق 50 متراً من الشباك **ولم يُغلق يوم العمل**، ثم ترسل الطلب برقم فاتورة عشوائي. |
| لوحة الكاشير | `cashier.html` | الطلبات مرتبة من الأحدث للأقدم مع تحديث **فوري** ونغمة تنبيه، أزرار تغيير حالة الطلب وأرشفته، **فتح/إغلاق يوم العمل** مع ملخص مبيعات اليوم عند الإغلاق. |
| شاشة المطبخ | `kitchen.html` | عرض فوري للطلبات الموجهة للمطبخ بعمودين (قيد الانتظار / قيد التجهيز)، الأقدم أولاً، مع مؤقت منقضٍ لكل طلب ونغمة تنبيه. |

قاعدة البيانات: **Supabase** (الخطة المجانية) — الاستضافة: **GitHub Pages** (مجانية).

## 🛠 خطوات التشغيل (10 دقائق)

### 1) إنشاء مشروع Supabase مجاني
1. ادخل إلى [supabase.com](https://supabase.com) وأنشئ حساباً مجانياً.
2. اضغط **New project** واختر اسماً وكلمة مرور لقاعدة البيانات.
3. انتظر حتى ينتهي تجهيز المشروع.

### 2) تنفيذ سكربت قاعدة البيانات
1. من القائمة الجانبية افتح **SQL Editor** ثم **New query**.
2. انسخ محتوى الملف `sql/setup.sql` بالكامل والصقه ثم اضغط **Run**.
3. السكربت آمن لإعادة التنفيذ: ينشئ جدول `orders` وجدول `work_days` (يوم العمل) ويُفعّل **Real-time** على الطلبات ويضبط الصلاحيات.
   (للتأكد: Database → Replications → يجب أن يظهر `orders` مفعّلاً).

> 🔁 إذا كنت شغّّلت النسخة السابقة سابقاً: أعد تنفيذ `setup.sql` فقط ليُضاف جدول `work_days` الجديد.

### 3) إضافة المفاتيح إلى Repository Secrets (بدون وضعها في الكود)
المفاتيح **لا تُكتب في أي ملف داخل المستودع** — بل تُحقن في `js/config.js` آلياً وقت البناء:

1. انسخ من Supabase: **Settings → API** → قيمتَي `Project URL` و `anon public key`.
2. في مستودع GitHub افتح: **Settings → Secrets and variables → Actions**.
3. اضغط **New repository secret** وأضف سرّين:

| Name | Value |
|---|---|
| `SUPABASE_URL` | `https://xxxxxxxx.supabase.co` |
| `SUPABASE_ANON_KEY` | `eyJhbGciOi....` |

4. الملف `js/config.template.js` يبقى في المستودع بعناصر نائبة فقط (`__SUPABASE_URL__`)، وملف `js/config.js` الحقيقي مستثنى في `.gitignore` فلا يُرفع أبداً.

### 4) الرفع على GitHub وتفعيل النشر التلقائي
1. أنشئ مستودعاً (Repository) جديداً — مثلاً `drive-thru` — واجعله **Public**.
2. ارفع الملفات كلها بنفس البنية (اسحب المجلدات في صفحة Upload، أو):

```bash
git init
git add .
git commit -m "Drive-Thru app"
git branch -M main
git remote add origin https://github.com/USERNAME/drive-thru.git
git push -u origin main
```

3. من إعدادات المستودع: **Settings → Pages → Source: GitHub Actions** (وليس "Deploy from branch").
4. افتح تبويب **Actions** في المستودع — ستجد سير عمل `Deploy Drive-Thru` يعمل تلقائياً مع كل `push` إلى `main`، وينشر الموقع على:
   `https://USERNAME.github.io/drive-thru/`

> ⚠️ إذا فشل النشر برسالة Missing repository secrets فهذا يعني أنك لم تُضف السرّين في خطوة 3.

### 5) الاستخدام اليومي
- **افتح اليوم:** من `cashier.html` اضغط "▶ فتح يوم العمل" — بعدها فقط يمكن للعملاء الطلب (وإلا تراهم رسالة "المطعم مغلق حالياً").
- **العميل:** يفتح الرابط الرئيسي من هاتفه ويسمح بالموقع — الطلب مسموح فقط داخل نطاق 50 متراً من الشباك.
- **المطبخ:** افتح `kitchen.html` على شاشة المطبخ — تظهر الطلبات فوراً، والأقدم أولاً، مع مؤقت لكل طلب.
- **أغلق اليوم:** نهاية الدوام اضغط "⏹ إغلاق اليوم" فتظهر نافذة **ملخص فواتير اليوم** (عدد الطلبات، المكتمل، إجمالي المبيعات) ثم اعتمد الإغلاق ليُسجَّل في جدول `work_days`.

## 🔊 ملاحظة مهمة عن صوت التنبيه

متصفحات كروت وسفاري تمنع تشغيل الصوت قبل أول تفاعل من المستخدم. لذلك:
> بعد فتح `cashier.html` أو `kitchen.html` اضغط **أي مكان في الصفحة مرة واحدة** (أو زر 🔔) لتفعيل نغمة التنبيه، وستعمل تلقائياً بعد ذلك لكل طلب جديد.

## 🧪 التجربة من المنزل

الطلب مقصور على 50 متراً من إحداثيات المطعم. للتجربة من مكانك الحالي:
1. افتح `js/config.js` (الملف المحلي).
2. غيّر `radiusMeters: 50` إلى `radiusMeters: 999999` مؤقتاً.
3. جرّب التطبيق كاملاً، ثم **لا تنسَ إرجاع القيمة إلى 50**.

💡 لاختبار رسالة "خارج النطاق" أيضاً: استخدم قيمة نطاق صغيرة مثل `1`.

## 💸 العملة والمنيو

- العملة الافتراضية **دينار أردني (د.أ)** بثلاث خانات عشرية (فلس) — تُعدّل من ملف الإعدادات.
- الأسعار والأصناف تُعدّل من `js/menu.js` فقط (الاسم، الوصف، السعر، الإيموجي، القسم) وستظهر مباشرة للعميل.
- إحداثيات المطعم ونطاق السماح: `RESTAURANT` داخل ملف الإعدادات.

## ⚠️ ملاحظة أمان

- **المفاتيح:** لا تُخزَّن في المستودع إطلاقاً — `js/config.js` مستثنى في `.gitignore` وعند النشر تُحقن من Repository Secrets داخل `js/config.js` المؤقت وقت البناء فقط.
- 🔁 إن سبق ورفعت مفاتيحك في النسخة القديمة: احذفها من `js/config.js` في المستودع، ويمكنك تجديد المفتاح من Supabase (Settings → API → Regenerate).
- **مفتاح anon** يبقى بطبيعته مفتاحاً عاماً يظهر في متصفح أي زائر — الحماية الفعلية للبيانات هي سياسات **RLS** في `sql/setup.sql`.
- سياسات الجداول **مفتوحة** (إضافة/تعديل/حذف بدون تسجيل دخول) وهذا مقصود لتبسيط التشغيل بدون حسابات؛ لأي تشغيل تجاري حقيقي يُنصح بإضافة Supabase Auth للكاشير وتقييد الصلاحيات.
- صفحتا الكاشير والمطبخ محميتان من الفهرسة (`noindex`) — احتفظ برابطيهما ضمن فريق العمل.

## ❓ حل المشكلات الشائعة

| المشكلة | الحل |
|---|---|
| ظهرت رسالة "التطبيق بحاجة إلى إعداد" | محلياً: الصق المفاتيح في `js/config.js`. عند النشر: أضف السرّين في Repository Secrets ثم أعد تشغيل سير العمل من تبويب Actions. |
| زر "فتح يوم العمل" يفشل | نفّذ `sql/setup.sql` مرة أخرى ليُنشأ جدول `work_days`. |

| الطلبات لا تظهر فوراً في الكاشير/المطبخ | تأكد من تنفيذ `setup.sql` ومن أن Real-time مفعّل (Database → Replications → orders). |
| لا يعمل تحديد الموقع | GPS يعمل فقط عبر HTTPS أو `localhost` — رابط GitHub Pages آمن تلقائياً. اسمح بإذن الموقع من المتصفح. |
| رسالة "خارج النطاق" وأنا في المطعم | انتظر ثوانٍ حتى تثبت إشارة GPS وأعد المحاولة؛ تأكد من صحة الإحداثيات في ملف الإعدادات. |
| لا يوجد صوت عند وصول طلب | اضغط أي مكان في صفحة الكاشير/المطبخ مرة واحدة بعد فتحها، وتأكد أن زر 🔔 مفعّل. |
